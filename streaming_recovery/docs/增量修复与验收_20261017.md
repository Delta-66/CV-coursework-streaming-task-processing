# 2026-10-17 增量修复与目标 1—3 验收

本轮在原 `streaming_recovery/` 上修改，没有另建并行系统，没有修改根目录业务代码或原变量名。根 README 只补充分路线进度，历史记录保留。交付结果不是“所有能力已完成”：固定场景的完整任务效果链已获得真实运行证据，真实联合定位及闭合准备仍未完成。

## 需求、核查与主要路线

| 目标 | 必须实现的功能 | 本轮改动与验证 |

## 确定问题与实际修复

| 审查问题 | 实际补丁 | 结果与边界 |
|---|---|---|
| A 遮挡仍开爪 | `recovery.py` 的当前有效性/可见性/时效/冲突门控，同时用于生成与运行时校验；`engine.py` 先过滤过期模态 | 同一历史失败在遮挡时只请求补观测，不能开爪；反向篡改结果也被拒绝 |
| B 历史持刀屏蔽新失败 | `tracking.py` 分离 `ever_held`、`attempt_held` 和当前 `held`；真实新尝试清除旧尝试的抓取/失抓上下文 | 历史成功后再次空手离开会产生新事件；建议本身不推进尝试 |
| C 一帧未知遗忘连接 | 保留最近可靠夹持锚点，默认有效期 4 s；当前未知另存为 `held=None` | 短缺口后分离可建立失抓；未知本身不失败，过期旧夹持也不能证明现在失抓 |
| D 旧小块算新切割 | 保留切割前布局，要求持刀作用早于新增效果；已有小块需额外的新效果比较 | 旧的误写测试纠正为“不完成”，另有真实新增效果正例；未把 yes 改成 unknown 规避 |
| E 完成状态锁死 | `completed` 为历史成就；当前 `returned` 随观测更新，输出 `historical_completion` 与当前 `task_completed` | 完成后刀离架/未知时不继续输出当前 completed；历史完成仍可保留 |
| 只有对齐、没有闭合 | `RecoveryContext` 保留一个事件；加入 `grasp_readiness`、准备检查、闭合建议和效果检查 | 完整推进链仅合成验证；2D 重合缺独立准备时不会闭合 |
| 全部恢复都假定在刀架 | 连接失效按当前砧板/其他支撑位置重新获取；未取到与缺前置条件采用对应策略 | 恢复位置、受阻步骤、继续原流程条件与当前状态关联 |
| 校验接受无根据参数 | 按动作校验对象、坐标、当前证据、必要前置条件、方向符号、参数和执行标记 | 开/闭爪不能夹带 translation/rotation；无物理数值来源时拒绝数值命令 |
| 指令四关键词误匹配 | 新增 `task_spec.py` 显式完整指令白名单与任务顺序/完成规格 | 否定、不同任务、歧义变体拒绝，不声称任意自然语言泛化 |
| 首帧失败后永久未知 | 起始 3 s 内可从之后已到达的合格观测校准，保留真实参考时间 | 缺失首帧故障注入已验证；任意中途布局不能倒填初始状态 |
| Qwen rack 枚举 | 原边界已存在 rack→holder；本轮统一提示为 holder，保留兼容映射并做不加载模型的回归 | 审查对直接 parser 的复现成立，但不能据此说既有真实适配器完全无映射；未验证新的模型语义可靠性 |

收尾还用反例确认并修复：已明确归位释放后，旧夹持锚点不能继续成为后来失抓的前件；历史完成仍保留，当前位置照常更新。证据见 released_connection_before.txt 与 delivery_unit_tests.txt。

## 真实视觉增加了什么

`geometry.py` 仍保留原单视角对照。新增 `multiview.py` 使用同一在线观察契约，没有样本名、结局、总时长或未来画面输入。

1. 顶视初始已接受图像建立砧板、刀架刃区及香肠几何参考。不是整段轨迹统计或人工逐样例答案。
2. 腕部窄长亮刀刃与两指尖端带的空间关系，加上原刀架刃区变化，支持当前刀具连接。开闭值仍来自原始状态，明确不是独立视觉夹爪分类器。
3. 刀刃与香肠端部相邻并发生相对运动，产生“刀具作用”的视觉代理；本身不等于已切开。可从两端切入。
4. 原主香肠仍存在且未被机器人遮挡时，比较新增、分离、近圆形小区域与初始布局；连续支持后确认本次效果。初始已有小块不计新增。
5. 刀架刃区外观恢复且可见，夹爪与刀分离，连续支持当前归位和释放。不会用最终成功标签或流结束补齐。

这些判据只在明确的固定场景假设下工作。颜色、形状和接触带是可审查的经典视觉先验，不是训练后的通用识别器。局部轮廓/掩码和相对运动可能受反光、遮挡及其他相似物体干扰；没有报告校准概率。输出引用当前两相机、初始参考和上一腕部证据，最多 4 项。像素区域质心没有被冒充为刀柄中心或两指中点。

## 两层建议和推进实例

真实 episode 0，9.6 s：

- 事件 `event-0001`，抓取尝试后刀仍在架上，机器人已到砧板；当前没有可靠夹持。
- 高层 `retry_tool_acquisition`：切割前置条件受阻，先在刀架重新建立定位、对齐和可靠夹持；只有连续新观测支持刀离架并随夹爪运动才恢复转移。
- 低层 `open_gripper`：当前刀与夹爪分离且夹爪闭合；执行器先确认夹爪内无其他物体及可安全打开，再保持末端位姿、单独打开。
- 坐标 `right_gripper_actuator_no_translation`；translation、rotation、numeric_command、units 都为 null。
- 检查实际打开、刀未被拖动、重新定位刀柄与两指。`actually_executed=false`，无回执，无效果归因。

[合成恢复推进序列](../artifacts/incremental_20261017/synthetic_recovery_trace.jsonl)显示：疑似保持 → 确认后开爪建议 → 实际观测已打开且未对齐时交接图像对齐 → 仅 2D 对齐时检查深度/姿态/接触准备 → 独立准备观测到达后建议闭合 → 观测真实开闭变化后进入抓取效果检查 → 连续连接证据后解除恢复上下文。它没有执行任何动作；其中准备传感证据明确标为合成。
