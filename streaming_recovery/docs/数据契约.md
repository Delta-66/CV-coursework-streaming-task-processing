# 当前契约 1.2：实测关节与条件腕部输入

旧变量和位置参数不变；`Observation` 末尾新增带默认值的 `observation_velocity`。源字段仍叫 `observation.velocity`，不改数据集字段名。缺失/无效/过期向量为 null，模态状态明确标记；不以目标 action/EEF 补值。

- 默认 25 Hz 顺序读完整轨迹，25 帧一次判断，即 1 Hz；采样末尾不足 1 s 仍顺序消费，不增加事后分析。源审计包含最后原生时间戳与实际读取列。
- `observation_inputs` 保存当前可用的 14 维 state / velocity 和共享传感来源声明；只有右臂六关节及 state[13] 用于本任务，左臂仅在原始向量中保留。
- `visual_facts.measurements.joint_motion` 包含当前速度、与窗口前一时刻位置的最大绝对变化、阈值、原始单位、至多 3 条传感引用。`moving` 表示当前速度越阈；`recent_motion` 只表示过去相邻间隔发生位置变化；两项均低才是 `stationary`；证据不足为 `unknown`。不是成功置信度。
- `state.arm_activity` 和阶段/诊断使用上述证据；新增 `approach_tool` / `holding_tool`。空手移动到工作区可以支持缺少前置条件，但运动/闭爪不能确认抓住。持刀回架、释放阶段不再以切割确认作为门槛，整任务完成仍严格要求本次切割效果。
- 实际当前图像按 `last_metrics.images_used` 记录；只有顶视刀架/抓取关系不清楚时咨询当前腕部。`model_input_images` 保守计入初始参考（当前顶视＋初始参考＋可选当前腕部≤3）。旧腕图引用用于审计，其像素不作为第四张图输入。
- 观测最多 4 条，state＋velocity 共最多 112 个数；关节特征引用最多 18 条、事件传感引用最多 48 条、恢复上下文传感引用最多 12 条，对齐器最新样本 4 个。其余 1.1 容量保留；每步检查全部容量。
- `processing.decision_wall_s` 是入口保存的程序处理耗时，不参与推理，不是视频检测延迟。`modalities_for_audit_only` 的腕图可在网页查看，但没有被查询的图不宣称参与判断。

# 契约 1.1 历史增量说明

保留原字段及程序变量名。`Observation.grasp_readiness` 是末尾带默认值的可选字段，旧调用无需修改；默认回放源不提供，也不伪造。`VisualFacts` 增加 `gripper_source`、`grasp_readiness`、`localization_frame`。旧模型 JSON 严格解析仍沿用原字段集合，不能随意追加模型生成的接触回执。

- `gripper_source=observation.state[13]` 表示夹爪开闭来自同一原始观测，不能称为独立视觉互证；`independent_visual` 才参与独立开闭冲突检查。
- `grasp_readiness` 为空时准备未知；非空必须恰好包含 `depth`、`orientation`、`contact_region`、`source`、`timestamp`、`ref`。前三项为 confirmed/unknown/not_ready。真实允许的来源为 measured_depth_and_contact / validated_controller_observation；当前没有相应适配器。合成来源只在 synthetic_test_double 事实中有效。未来时间戳被拒绝，闭合建议要求本时刻新鲜证据。
- `knife_handle_xy` 与 `gripper_xy` 是同一图像坐标系内 0..1000 的点；默认 `cam_high_image_x_right_y_down`，也允许右腕图像系。当前真实后端没有可靠联合定位，二者保持 null。
- `measurements.food_components[*].bbox`、初始食物 bbox、`wrist.blade` / `wrist.food` 为处理后图像的像素 xywh，不是上述归一化点，更不是物理坐标。窗口图像为最长边 512；不由这些框生成数值机器人动作。
- 双视角证据引用最多 4 项：当前两图、初始参考、上一腕部图。模型实验仍最多输入 3 张图。扩展 measurements 单条序列化最多 9,000 字符；特征总 payload、事件、恢复上下文和几何记录也检查容量。
- `state.historical_completion` 是历史成就；`state.task_completed` 是当前完成条件。`attempt_held` 仅表示当前尝试，`ever_held` 不替代当前夹持。`returned` 当前可以为 true、false 或 null。
- `recovery_event` 单独保留一次失败的恢复上下文；实际新尝试使原 failure_event 关闭后，仍可生成该次恢复的效果检查建议，不假定新动作成功。

- 当前主后端 `multiview_effect_geometry` 真正使用 cam_high、cam_right_wrist 和 state[13]；旧 calibrated_rgb_geometry 保留为受限对照。默认每10帧处理一次（2.5 Hz）；原生时钟和0.12秒过期边界不变。

# 在线数据与输出契约

## 数据源边界

`Observation` 包含 `timestamp`（秒）、`instruction`、`images`（当前已到达的 PIL RGB 图像）、`observation_state`（14 维实测状态或 `None`）、`modalities` 和轨迹内 `ref`。不包含路径、episode 编号、总帧数、结果标签、动作目标、最终阶段或外部审计日志。

`source.py` 保留原数据字段 `observation.state`；`observation_state` 是新 Python 数据类的成员，不修改用户现有程序。Parquet 只读取 `timestamp`、`frame_index`、`observation.state`；任务检索在控制面另读第一行 `task_index`。

异步 `Sample` 用 `timestamp` 标注传感器样本时间、`arrived_at` 标注到达时间；两者均必须不晚于当前时间。无效值携带 `valid=false` 和 `reason`；只保留每种模态最新样本。结果中的模态状态是 `available` / `missing` / `stale` / `invalid`，包含实际时间戳、年龄和原因。

本地 LeRobot 回放使用经逐帧核对的共同 25 FPS 时钟。它不会自动适配未标定的异步传感器目录：接入新数据需要提供真实时间戳与到达规则，不能静默假定同步。

## 视觉契约

`VisualFacts` 固定包含：

- 当前 `timestamp`、`ref`、`valid`、`error`、`provenance`；每个证据有相机、时刻、观测引用。
- `visibility`、`knife_location`、`gripper`、`motion`、`contact`、`co_motion`、`cut_piece`、`released`；未知使用枚举 `unknown`。
- `knife_handle_xy`、`gripper_xy`：只能为当前高位相机图像中 `[0,1000]` 归一化位置或 `null`；不是物理坐标，也不是控制命令。
- `measurements`：主视觉模型实际计算的区域变化比例、区域占用比例、像素运动、首帧参考及场景假设。
- `description`：有限长观察说明；`effect_usable` 表示是否可用于效果判断。模态冲突后为 false，后续连续证据统计不能再用这一帧。

主模型不提供可靠刀柄/两指点定位，所以两个定位字段为 `null`；刀与机器人区域的质心只用于像素运动关联，不能伪装成精确抓取位置。`co_motion` 是区域运动代理，在场景假设下支持夹持推断，不是实测 EEF—物体刚体变换。

模型原始输出和已确认任务事实是两层信息：前者是识别结果，后者需要时序证据门槛；两者都保留来源和限制。

主经典视觉后端的 `gripper` 来自 `observation.state[13]` 的原始值门槛，不是另一个独立的图像夹爪分类器。模态冲突分支用于可提供独立视觉开合判断的替换后端，当前由合成输入验证；不能把相同原始值派生的两个字段当作两个独立证据。

## 每次决策的输出

| 字段 | 含义 |
|---|---|
| `schema_version`、`timestamp`、`observation_ref` | 格式与当前时刻 |
| `method`、`instruction`、`scope` | 方法、任务和实际支持范围 |
| `state.stage`、`stage_zh`、`subtask` | 当前阶段与子任务，可未知或回退 |
| `state.confirmed_subgoals` | 已获得证据的子目标，不给虚构百分比 |
| `state.preconditions` | 当前可靠夹持（true/false/null）、切割效果、归位状态 |
| `state.known_facts`、`unknowns` | 有证据事实与待补信息 |
| `state.expected_effect`、`evidence`、`anchors` | 预期效果、当前证据、固定容量历史锚点 |
| `state.attempt`、`new_attempt_observed` | 由实际观测识别的尝试次数与边沿 |
| `execution_status` | executing / information_insufficient / suspicious / confirmed_failure / recovered / completed |
| `failure_event` | 稳定 ID、类型、尝试号、状态、证据及当前是否仍可观察；没有事件为 null |
| `notify`、`notification_reason` | 是否主动提醒及触发原因 |
| `diagnosis` | 问题、预期偏差、证据、确定事实、未确认原因、还需什么信息 |
| `correction.high_level` | 受阻子任务、失效前置条件、影响、恢复子目标、理由、恢复主任务条件 |
| `correction.low_level` | 同一恢复子目标的一个下一动作、对象、坐标系、前置条件、停止条件、后置检查 |
| `execution` / `correction.execution` | 建议模式、未实际执行、无执行回执、不归因原视频结果 |
| `modalities`、`modalities_used` | 哪些模态可用、哪些实际用于判定 |
| `memory_usage`、`memory_limits` | 所有推理历史容量使用和声明 |

正常执行不强行产生纠错；无建议为 `correction: null`。无物理坐标映射时，`numeric_command`、`rotation`、`units` 等为 `null`，而非凭空给数字。动作前置条件既包含当前已支持条件，也明确列出需要执行器检查/尚不满足的条件；因此建议不是可直接下发的控制命令。

## 事件状态

`suspected → confirmed → persistent` 表示同一问题证据增强和持续；新确认会提醒，持续同类证据不重复提醒。明确正向持刀证据可使事件 `resolved`（原确认失败）或 `retracted`（原疑似）。实际打开并在刀架附近重新闭合可开启新尝试，旧事件记录 `closed_for_retry`，它并不表示故障已经修复。

缺帧使事件 `observation_status=unobservable`，不会因此清除；新的不支持证据令其 `not_currently_supported`，等待明确恢复证据。真正出现另一类问题可以 `superseded`，事件总数仍受容量限制。建议文本不会参与状态更新。

## 审计与推理分离

运行器把路径、源文件哈希、外部轨迹编号写入 `summary.json`，这些字段不传给 `Monitor`。`report.py` 在运行完成后读取 JSONL 生成查看页；验证器可以独立读最终标签，但不会把标注、检查结论或历史日志交给推理对象。
