# 流式任务理解、失败诊断与分层纠错：独立可运行实现

本目录实现目标 1—3 在**固定场景的右臂取刀、携刀转移及夹持前置条件监测**上的完整链路。采用真实像素驱动的经典视觉模型和有界状态机，不训练模型，不接入真机，不把建议视为执行。原项目代码、变量名和未提交成果均保留。

两个真实开发样例已跑通：失败轨迹在 9 s 疑似、10 s 确认；正常轨迹无失败提醒，11 s 开始获得持刀证据。**这不代表整项切割任务已验收，也不是泛化准确率**。切割完成、刀具归位、真实重试和滑落还缺少相应视觉验证。详细结果及证据见 `docs/验证与交付.md`。

## 运行

在项目根目录 `C:\Users\lenovo\Desktop\CV` 的 PowerShell 中：

```powershell
& 'C:\Users\lenovo\.conda\envs\cv-streaming\python.exe' -m streaming_recovery run
```

这会读取现有真实数据，逐帧解码，输出 33 个在线决策和可离线查看的 `index.html`。主方法在 CPU 上运行，无需 GPU 或 API 凭据。每次新建时间目录，不覆盖旧结果。

完整功能验证：


可用 `--config 路径` 和 `--output 新目录` 指定配置、输出；已存在的输出目录会拒绝覆盖。配置中的相对路径相对于配置文件。迁移机器时安装本目录 `requirements.txt`，用 Python 3.11，然后修改 `source.root`。原有 `cv-streaming` 已具备全部依赖，本次未安装或修改环境。

## 输入与已验证的数据边界

本地 `data/vifailback_lerobot` 的 LeRobot v2.1、25 FPS、640×480 AV1；episode 0 和 18 分别 300、519 帧。指令经第一行 `task_index` 查 `meta/tasks.jsonl` 得到。在线读取只允许 `timestamp`、`frame_index`、`observation.state`；源字段未重命名，Python 契约用 `observation_state` 搬运其中的值。

主方法使用 **cam_high 图像＋`observation.state[13]` 右夹爪原始值**。`cam_right_wrist` 同步读取并保存供人工核查，未用于主判定；不会将“可用”与“实际使用”混写。左右腕部视频、关节速度/effort 和目标 EEF 虽存在，主方案没有使用。

`action` 是下一步 qpos，`complementary_info.action_eef` 是目标 EEF，均不输入诊断。没有核实的机器人坐标、物理单位和标定不能从这些字段推定。完整数据事实、一手来源及缺失信息见 `docs/需求与事实.md`。最终标签和 avoid/correct 标注只在独立验证器完成推理后读取。

## 方法与因果性

方法名是 `bounded_visual_state_tracker`，不是纯滑动窗口或纯当前观测基线。图像工作区只从 `t=0` 已到达图像初始化；保留一个固定参考图像、三个掩码和两个短时目标轨迹。后续分割与差分都针对当前图像；不会看完整视频选帧、按全段统计归一化、用未来平滑或按总时长推测阶段。

视觉模型的显式场景假设是：顶视相机固定、初始砧板/刀架可见，棕色砧板右侧有狭长黑刀架，白柄刀是进入板面的唯一大块浅色细长工具。HSV 颜色和形状先验、首帧差分、机器人与刀像素的运动关联共同产生证据。这是**未经训练的场景专用经典视觉基线**，不是通用语义检测器；相近颜色干扰物、手部介入、照明变化和相机移动会影响判断。

首帧校准失败或从中途开始时明确报告未知并要求从有效初始帧重启，不能悄悄用后来的任意状态替换初始条件。大幅背景改变/黑屏会降级为信息不足。原始测量、参考帧和阈值均在结果中可核查；像素质心不会冒充夹爪中点或刀柄定位。

原生帧按 25 FPS 顺序到达；默认每 25 帧决策一次，即数据时间 1 Hz。适配器逐帧检查视频 PTS 和表格时钟，浮点舍入只容许 `1e-5 s`，决策时间用经验证的帧时钟。错位、缺帧和非有限值显式标记。异步对齐器仅接受时间戳不晚于到达时间、且已经到达的样本；过期阈值默认 0.12 s，无未来插值。

回放用同步背压：本次处理完成后才推进输入。它保证因果次序，不承诺真机 25 Hz 实时吞吐。末帧不会因提前知道总长度而额外触发一次判断；流结束也不触发成功。编解码器/Arrow 有内部运输缓冲，但没有接口将未到时刻的像素/行交给推理；已对整个处理链进行公共前缀测试。

## 所有推理历史的容量

| 项目 | 默认上限与规则 |
|---|---|
| 近期观测 | 4 条，且不超过 4 s；每条至多两张、长边 512 的图像 |
| 近期视觉事实 | 6 条，且不超过 4 s；每条描述 ≤400 字符、错误 ≤500 字符 |
| 长期任务证据锚点 | 8 条，固定语义键更新；每个至多 3 个图像引用，不保留图像副本 |
| 事件 | 4 条（含当前）；每事件 4 条证据，满容量淘汰最旧事件 |
| 固定任务/对象状态 | 12 个状态槽、3 个语义对象，不追加对象清单 |
| 视觉后端 | 1 张首帧参考、3 个固定尺寸布尔掩码、2 个点轨迹；每轨迹只保存上一时刻 |
| 对齐器 | 当前 state 和两相机各一个最新样本；不存异步无限队列 |
| 指令与模型文本 | 指令 ≤1000 字符；主方法无模型提示/对话历史 |
| Qwen 实验接口 | 单请求/响应队列；≤3 张图、4096 输入 token、384 输出 token；原始回答 ≤6000 字符；无跨调用 KV 缓存 |

所有决策输出 `memory_usage`。参考图像可以早于滑窗，但明确属于额外声明的一张有限记忆，不能把本方法称为纯滑窗。磁盘审计日志可以累计；`engine.py`、`tracking.py`、`geometry.py` 不读取它。离线报告和验证器可以读日志，不把结果回灌推理。解码器与当前算子的固定临时数组不算历史，且不随轨迹长度增长。

## 阶段、诊断与阈值

阶段由实际证据支持：寻找/接近、对齐、抓取尝试、抓取确认、携刀进入工作区、效果待检查；允许回退、未知及实际重试，不输出虚构百分比。全任务切割/归位/完成规则存在，真实主视觉后端对这些证据保留 `unknown`，因此不会宣称整任务完成。

右夹爪 `0.04`/`0.025` 是明确配置的原始值开/闭门槛，`0.012` 是闭合变化量门槛；是根据本地样例图像和原始状态的对应关系选择的工程阈值，不是米、弧度、夹持力或概率。只有刀架附近实际观测到打开→闭合，才登记新尝试。闭合本身不能确认持刀。

失败主类：`grasp_not_established`，必须看到尝试后机器人进入板面工作区，刀具源区域仍保持原样，且未出现工具随同进入工作区。只有任务暂未完成、夹爪未动、接近耗时或刀架被遮挡均不足以确认失败。正常持刀则要求刀具离架的视觉关联、浅色工具进入板面、机器人与刀像素共同运动，以及夹爪观测闭合，连续支持后才确认。运动关联是场景假设下的像素代理，不是已标定的 EEF 轨迹。

确认默认需要两个不同决策时刻、跨度 ≥0.8 s、相邻间隔 ≤2.1 s；缺失/冲突会打断候选证据连续性。首个证据触发疑似，第二个充足证据触发确认，之后同一事件持续更新而不逐帧提醒。只有实际新尝试才生成新的失败事件；建议中的“重试”不会改变尝试计数。

`prerequisite_unmet` 与 `lost_grasp` 规则有合成测试，未以相应真实轨迹证明识别能力。失败事实与原因假设分开：不能从“刀仍在架上”断言摩擦不足、夹持力过小。没有输出未经校准的置信概率。

## 分层纠错

高层和低层共享 `event_id`、`recovery_goal_id`、`object`。低层只发出下一动作，不一次承诺一串尚未检查的动作。疑似时保持/重新观察；真实确认失败样例中，刀仍在架上且空夹爪已闭合，因此建议在执行器确认安全条件后先打开右夹爪，为重新对齐建立条件。

图像对齐建议接口只接受当前图像中可靠的刀柄/两指位置，方向限定 `cam_high_image_x_right_y_down`，没有物理位移、角度、速度或夹持力数值。主经典视觉模型不把区域质心充作刀柄/夹爪定位，因此该分支目前仅合成验证；补齐可靠局部定位与标定之后才能升级精确动作。打开夹爪和保持/重观测不要求虚构三维坐标。

每条建议包含动作前置条件、停止条件、执行后检查，以及明确的 `directly_executable: false`。回放始终 `actually_executed: false`、`execution_receipt: null`；原视频后续即使恢复，也只记录观察变化，不归因于建议。

## 为什么不用本地 VLM 作为主判定

已真实调用 Qwen3-VL-2B 两轮，各 17 次，覆盖正常与失败轨迹。第一轮出现刀架位置与共同运动的矛盾；第二轮出现缺字段、物体关系矛盾和不可靠空间描述，均未获得可用于验收的严格有效输出。原始文本完整保存在 `artifacts/probe_v1.jsonl`、`artifacts/probe_v2.jsonl`。这只说明这两版提示和本地设置未奏效，不是对模型整体能力的评测。

`vision.py` 保留真实本地模型接口、长度限制、JSON/坐标/矛盾检查和独立 worker 超时终止。模型加载或推理失败显式变成未知，不能回退为伪造结果。若需复现新一轮试验，使用 `cv-baseline` 执行 `python -m streaming_recovery.probe --output 新的.jsonl`；这不是主验收命令。
